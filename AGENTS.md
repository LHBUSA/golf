# PropBetEdge Golf engineering contract

GitHub is source; Vercel serves the frontend; Cloudflare Workers run APIs, ingestion, automation and news. Supabase SPORTS is the canonical graph. All golf tables use `golf_*`. Never store sports data in identity/billing Supabase. R2 archives immutable evidence; KV caches disposable state.

Soccer and tennis sibling repositories are read-only references. Purpose-build golf.

No fabricated scores, players, rankings, tournaments, statistics, quotes, injuries, photos or shot locations. Missing means null/unavailable. Provider IDs are crosswalks, never canonical identity. Never merge people by name alone; uncertain identity goes to review.

Audit each source before ingestion: registry, access evidence, licence/commercial redistribution assessment, cadence, coverage, identity and provenance. Stop on 401/403, login, bot challenge or other access barrier. Never evade or retry around barriers. Paid APIs and new licence obligations need owner approval.

Each image requires source, author, licence, attribution, identity proof and approved rights status. No unclear-rights hotlinks or mock athlete photographs. Use an original identity treatment when imagery is unavailable.

Golf is included in existing PropBetEdge All Access / Pro Club. No golf-only checkout or Stripe product. Enforce premium access server-side before returning values; never hide returned premium data with CSS.

News requires frozen evidence, deterministic facts, numeric claim validation, materiality, duplicate suppression and quality gates. No invented claims. Analytics require versioned methodology, cohort, season, tour and sample coverage. Course Fit starts descriptive. Shot views use observed events only.

No GitHub Actions Worker deployment. No production deployment, resource creation, migration application, publication, data purchase or licence acceptance without owner approval. Draft migrations and undeployed Worker foundations are authorized. Commit and push safe repository work are authorized.

Maintain immediate static shell, progressive data loading, explicit image dimensions, responsive and accessible controls. No thin autogenerated SEO pages. Verify `npm run check`, `npm run build`, `npm run test`, `npm run qa:browser`, `npm run guard`; browser widths 320, 360, 390, 430, 768, 1024, 1440 must have no horizontal overflow or console errors.

- Golf news HTML is rendered by the `golf-api` Worker. Any change to server-side SEO or article rendering (`src/lib/render.js`, `seo.js`, `article.js`, `image-metadata.js` and what they import) needs the Vercel deploy AND a fresh `golf-api` deploy from the same commit. See docs/RELEASE.md.
